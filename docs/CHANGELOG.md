# LAIUNI Translator — Changelog

Changes to the code in this repository. Earlier history is in the git log.

## Sprint 20 — flexible frontend deployment: two ports, signed backend surface, address-only registration (§14, ADR-023) (2026-10-30)

Port of HRDD Helper Sprints 35–36 with the same protocol; Translator-specific parts noted.

- **Images:** new `build-frontend.yml` publishes `ghcr.io/dfergo/laiuni-translator-frontend` (amd64 + arm64; React built once with `--platform=$BUILDPLATFORM`), tags `latest` and `sha-<short>` from `main`. `build-backend.yml` keeps its names and tags; its `paths` filter now includes `.dockerignore`. `docker-compose.frontend.yml` pulls the published image.
- **Frontend (two surfaces):** port `80` serves the portal and browser routes; port `8080` serves only `/backend/v1/*`. `sidecar/backend_auth.py` verifies `X-HRDD-Timestamp` / `X-HRDD-Nonce` / `X-HRDD-Signature` (±120 s, nonce cache, pre-start signatures rejected, generic 401) at ASGI level; `sidecar/serve.py` runs both apps in one process; Nginx has two `server` blocks; supervisord runs `python -m sidecar.serve`. Env: `BACKEND_SURFACE_AUTH`, `TRANSLATOR_BACKEND_SECRET`, `TRANSLATOR_BACKEND_SECRET_PREVIOUS`. The queue reports `surface_auth`.
- **Removed routes** (no caller in Translator): `POST /internal/queue`, `GET /internal/stream/{t}`, `POST /internal/stream/{t}/chunk`, `POST /internal/session/recover`, `GET /internal/session/{t}/recover`, `POST /internal/session/{t}/recovery-data`, `POST /internal/auth/request-code`, `POST /internal/auth/verify-code`, `GET /internal/auth/status/{t}`, `POST /internal/upload/{t}`, `GET /internal/uploads`, `DELETE /internal/evidence/{t}/{f}`.
- **Backend:** `services/frontend_client.py` rewrites `/internal/X` → `/backend/v1/X` and signs per the registry entry's `auth_mode` (`signed` with own or installation secret `TRANSLATOR_FRONTEND_SECRET` — fail closed without one; `unsigned`; `legacy`). Entries without a mode: secret → signed, none → legacy. Polling, the job channel and the admin pushes all go through it.
- **Result size:** backend surface accepts up to 512 MB (middleware + Nginx); the middleware accumulates the body in a `bytearray`. The backend measures the result ZIP before pushing: above the limit (or on a 413) the user's portal shows the size and the limit (`done.errTooLarge`, 17 languages) and the backend logs a warning. Measured worst case: 25 MB document × 16 languages = 414 MB.
- **Registry + admin:** `auth_mode`, `signing_secret`, `extra_headers` and `public_url` on register/edit; secrets write-only; one verified save (URL + public address + mode + credentials); `global_secret_configured`; Security panel, mode badges and "frontend accepts unsigned". The emailed download link uses `public_url` (fallback `url`), with a warning when a non-legacy frontend has none. Configuration exports are documented as containing secrets.
- **Deploy:** two-port frontend compose (`FRONTEND_BACKEND_PORT`, `BACKEND_BIND`), `TRANSLATOR_FRONTEND_SECRET` in the backend compose, `deploy/` with T1 (LAN), T2 (VPS + cloudflared + Watchtower with `DOCKER_API_VERSION=1.44`), T3 (same host) and a README with what each mode gives up. Frontend examples use `mem_limit: 1536m` (results are held in memory, ≈2.5× peak).
- **Docs:** installation guide `docs/INSTALL.md` and `README.md`.
- **Admin → LLM:** the model `<select>` + "Enter manually" field is replaced by one searchable field (`ModelCombobox`).
- **Gate:** 26 sidecar + 41 backend unit tests, including the shared signature vector (`v1=c8cfb97d…5a02`, same as HRDD). Local Docker e2e on an internal network with the new image in each mode and the previous image as legacy: registration by address only, own secret, trusted network, clear errors (unsigned vs signed frontend, public port, wrong secret), polling, 401 / replay 401, 25 MB upload and signed fetch, 395 MiB artifact pushed and downloaded intact, >512 MB → 413 in the portal, restart with persisted config and languages and pre-restart signature rejected.
